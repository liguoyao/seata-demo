# 支付与取消仲裁

订单行是业务决策依据，支付行保存资金事实，库存预留行保存资源事实。

订单与支付使用行锁、前态检查及 MyBatis-Plus @Version 乐观锁，状态推进失败时回滚整个本地事务；Inbox 与事务消息的持久化提交决策同步回滚。

- 支付先于关闭决定到达订单：进入 PAID_PENDING_STOCK_CONFIRM；收到 STOCK_CONFIRMED 才完成。迟到的关闭结果不能覆盖已接受的支付。
- 关闭决定先到达订单：进入 CANCEL_PENDING_STOCK_RELEASE。即使尚未释放库存，后续支付成功也进入退款路径，避免确认库存与释放命令并行造成相反动作。
- 已取消后迟到支付：保留支付成功事实，固定退款单号，等退款和库存释放均确认后进入 REFUNDED。
- 支付创建与关闭乱序：关闭意图先持久化。未创建过的支付不再开放；已有创建任务未决时，关闭任务必须等待其结果被解析。
- UNKNOWN 不等于未付款。渠道查询/关闭任务持续重试，不直接释放库存。
- 库存释放后禁止重新预留；迟到确认返回 STOCK_CONFIRM_FAILED，由订单退款补偿。

完整架构和运行步骤见 README 与 transaction-redesign.md。
